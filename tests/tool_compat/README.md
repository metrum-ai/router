# Tool-call compatibility matrix data

`matrix.json` is the single source of truth for the published
[tool-call compatibility matrix](../../docs-site/docs/evaluation/tool-call-matrix.md).
Nothing in this directory runs a provider; the page and every check are
generated by `scripts/tool_compat_matrix.py`.

## Rules a cell obeys

- **A client surface states every caller path.** Every client declares the
  caller surfaces it is actually run on, and each of those must have a cell for
  same-dialect traffic and for every bridge direction from that surface. A path
  with no result is a cell with `tier`/`status` `not-covered` and a written
  `reason`. The check fails if a path is simply missing.
- **One tier per cell, never merged.** `mock` (scripted upstream), `unit`
  (local conversion check, no endpoint), `live` (real provider run), `unsupported`
  (declared by a doc line) or `not-covered`. A mock result never counts as live
  evidence, and a live cell is one recorded run on the named commit, not a rate.
- **A failure has an issue.** `status: fail` needs an `issue` number. A live
  report that fails without one is recorded with `live.triage_required`, and the
  check refuses it until someone opens the issue, so a red cell cannot quietly
  become documentation.
- **An unsupported cell cites the line that says so.** `doc` is a repo path plus
  a heading anchor, and the check verifies both exist.
- **Every number has a source.** A live cell carries `live.cost` with
  `source` (`usage_rows`, `provider_invoiced`, `estimate`, `not_recorded`) and
  `scope` (`cell` or `run`). `estimate` must say "invoice pending"; a null cost
  is only valid for `provider_invoiced` or `not_recorded`.
- **A claimed pinned-tester suite exists.** `suite` is only valid on the two SDK
  tester clients, and the name must appear in `scripts/compat_mock.py` `TESTERS`.

## Commands

```sh
python3 scripts/tool_compat_matrix.py --check     # validate + page is not drifted
python3 scripts/tool_compat_matrix.py --write     # regenerate the page after editing matrix.json
python3 scripts/tool_compat_matrix.py --compare old-matrix.json   # fail on a regression
python3 scripts/tool_compat_matrix_test.py        # unit tests
```

## Live report schema for the automation

An authorized live run records its per-cell outcome, and the matrix derives the
published page from it:

```json
{
  "schema_version": 1,
  "date": "2026-11-03",
  "commit": "4c950276f5e9e3fc70b72ed06d4721fea0720da8",
  "runner": "agent-tool-compat-live",
  "cost": {"usd": 0.0018, "source": "usage_rows", "scope": "run"},
  "cells": [
    {"id": "pi-chat-same-dialect-stream", "status": "pass", "detail": "depths 0,1,2,3,5"},
    {"id": "langgraph-chat-to-messages-stream", "status": "fail", "detail": "SSE tool-call deltas missing"}
  ]
}
```

`runner` is one of `agent-tool-compat-live`, `parallel-tool-live`,
`compat-live` or `manual`. An `id` that is not in the matrix fails the ingest
instead of inventing a cell. Ingesting with `--write` regenerates the page; use
`--compare` with the previous matrix in the same job to fail the run on a
regression rather than on any single flake.

The nightly workflow (`.github/workflows/agent-tool-compat-live.yml`) runs the
live gate, converts it with `scripts/tool_compat_live_matrix.py report`, ingests
the result and compares it against the committed baseline. It is main-only,
uses the protected `evaluation` environment, reserves before every dispatch,
and refuses to start once the monthly ceiling recorded in its ledger is spent.
