# Governance: scoped callers, redaction, quotas and audit

This loopback demonstration runs the real router and existing escalation policy
against a fake upstream. It checks a scoped caller's allow/deny (200/403), daily
request cap (429), a separate caller's token reservation rejection (429), RPM
limit (200 then 429), an authorized security CSV export and denial of that export
to a normal caller. A synthetic email is redacted before it reaches the fake
upstream; the usage DB records that a PII rule matched. Routing-decision
telemetry records `length:local`, a rule label, not an explanation generated by a
model. `local` is the policy's tier name even when the target is hosted.

`config.example.json` drives the demo setup. The script builds its actual router
configuration in a private temporary directory; it is **not a production config**.
Local-only basic admin credentials are public demo credentials. Never expose this
router or reuse these credentials. The tiny email regex is not a general-purpose
PII detector or a data-loss-prevention guarantee. Security reports can contain
IP addresses and identities: only a summary, not the CSV, is printed.

## Run

From the repository root (Go, Python 3 and PyYAML required):

```sh
go build -o /tmp/router-governance ./cmd/metrum-ai-router
python3 examples/governance/run.py --router /tmp/router-governance
bash examples/governance/oidc-smoke.sh
```

The OIDC command is a **separate integration test**, not the demo login: it uses
a synthetic loopback issuer to test the router login/callback/logout and
OIDC-session/Casbin authorization for admin reports. No real identity provider is
contacted. Configure a real HTTPS IdP and least-privilege admin policy according
to the router's administration documentation before deployment; this sample has
not tested that integration. Use a dedicated sandbox, inspect audit retention
and access rules, and obtain security review before applying the example.

For a loopback OpenAI-compatible self-hosted service, substitute `--backend
local --local-url http://127.0.0.1:PORT/v1 --local-model MODEL --state-dir
/absolute/private/new-dir`. No token prices are assumed; displayed zero excludes
inference and infrastructure cost. An end-to-end fake self-hosted test is included.

For a **paid** Fireworks smoke, set `FIREWORKS_API_KEY` privately in the process
environment and add `--backend fireworks --state-dir /absolute/private/new-dir`.
It sends two synthetic, bounded requests after PII filtering. Router telemetry
records the PII match, but the hosted service's received bytes are not separately
inspected. The script preserves state on failure or success for cost reconciliation;
it includes sensitive tokens/config/logs, must be access-controlled and removed
when done. The output's reported token cost uses dated configured list prices,
not a provider invoice, taxes or infrastructure. Check current model availability
and pricing before running; any retries or partial failure require reconciliation.
Do not print or publish the state directory or CSV.

## Evidence and limits

`evidence/` contains sanitized mock, OIDC and hosted smoke results, including
usage-derived cost and its limitations. The mock upstream checks
that the sample email is absent and a placeholder is present; this does not prove
all PII is removed. The local test replaces the upstream with a loopback fake,
not an actual local model. OIDC and demo are two separate processes. The route
label records a selection rule, not full causal trace or identity-policy proof.
The audit example validates authorization and basic absence of the known sample
email/tokens, not comprehensive export sanitization. Request/token quotas and
RPM limits are not dollar budgets. See the other catalog examples for usage-cost
and domain routing controls.
