# Release certification

Certify the bytes that operators install. Record the tag, full source commit, release workflow run and OCI index digest before selecting cases. For v5.0.0-rc.3 the commit is `02aeae9ba70bb87d71a239b2d4b1bfd52d5f821a` and the index is `ghcr.io/metrum-ai/router@sha256:239011e4a0184e42d62fd40bc95a0aa5d76dda009527002b1ba294ecdaeac926`.

1. Download the release archives and their signed inventory. Run `gh attestation verify <archive> -R metrum-ai/router --source-digest <commit>` before extraction. Verify the selected platform, artifact digest and source identity. Verify the image attestation using its OCI digest and use that digest for container runs. Retain verification output. A missing prerequisite leaves dependent cases unrun.
2. Read CATALOG.csv. Select every core case and identify extended runs before execution. Extended cases require a stated reason for selection or omission. Provision the declared database or hardware when required. Use isolated databases, synthetic data and the production service UID for upgrades. Resolve each supported production baseline to its own verified release. Exercise migrations with debug logs and parse stdout as exactly one JSON value. Restore backups and prove the old service can serve after rollback.
3. Execute the action in each row against the published target. Run source-level checks from a detached checkout of the exact release commit. A source test supplies evidence only for the conditions it exercises. Exercise remaining conditions through the published service or inspect the specified release evidence. Never substitute a locally built binary for a candidate. For issue-wide checks, inspect the linked implementation PR, its test runs, release docs and affected output surfaces.
4. Copy results/header.csv to results/<version>-<area>.csv. Record each catalog ID in that area, status, tag, commit, artifact digest or source identity, run ID, command, observed output excerpt and evidence reference. Redact credentials and payloads. Record PASS when all assertions hold. Also record PASS when the product removes the risk by design and therefore prevents the case precondition from being created. Explain that design and cite its evidence in the result notes. Record FAIL when the product mismatches a documented expectation. NOT-SELECTED means no completed run, including missing prerequisites. Record the reason. Missing core results prevent certification.
5. When a harness error invalidates an attempt, record INVALID-RUN and its reason in the evidence. Examples include a missing documented grant, an uninitialized service, or the wrong fixture. Retain the original attempt and use a clean rerun to determine the case status. Never delete a product FAIL. Preserve each failed run and its original expectations, fixtures, thresholds and gate configuration. Track fixes separately and rerun on a new candidate. Before GA compare source, asset and image digests with the candidate evidence. Carry forward only results whose tested inputs are identical. Repeat publication metadata checks on the final release and rerun affected cases for any changed inputs. A release with outstanding core failures or unrun core cases lacks certification.

The CSV header is the first record in each CSV file. The catalog uses stable IDs within each area. A value of `none` calls for direct execution or evidence inspection. Each result refers to a single candidate and run.

Core cases are mandatory GA gates. The catalog selects upgrade, CLI, configuration and packaging checks, paired real-handler security scenarios, the admin permission matrix and concurrent audit export, endpoint-family smoke tests and the performance gate. Every other case is extended. Shared documentation checks list their source issues separated by a vertical bar. Review each issue's acceptance evidence alongside the four shared documentation checks.

For GA, create an annotated tag whose message carries the v5.0.0 section of CHANGELOG.md. Verify the published release body against that section. Preserve the release-note failure on rc.3 in its original results.
